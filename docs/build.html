Bastille / Build & CI

Build locally
or in the cloud.

Reproducible builds via Docker + live-build. GitHub Actions pipelines for both x86_64 and ARM64, producing hybrid ISO artifacts on every push.

Local build

Build from source with Docker.

The build runs entirely in a Debian container — no host-side dependencies beyond Docker. The Dockerfile.build at the repo root sets up live-build and all required packages. Output is a hybrid ISO at build/live-image-*.iso.

01

Clone the repository

git clone https://github.com/ker0s3ner/bastille.git
cd bastille
02

Build the Docker image

docker build -f Dockerfile.build -t bastille-builder .
03

Run the build

Pass the target architecture via ARCH. The build writes the ISO to ./build/ on the host.
# x86_64
docker run --rm --privileged \
  -v "$(pwd)/build:/build" \
  bastille-builder amd64

# ARM64
docker run --rm --privileged \
  -v "$(pwd)/build:/build" \
  bastille-builder arm64
04

Write to USB

Replace /dev/sdX with your USB device. This is destructive — verify the target first with lsblk.
sudo dd if=build/live-image-amd64.hybrid.iso \
  of=/dev/sdX bs=4M status=progress
sync

GitHub Actions CI

Two pipelines. Both architectures.

Two separate workflow files handle x86_64 and ARM64. Each runs on a native runner — ubuntu-24.04 for x86_64 and ubuntu-24.04-arm for ARM64 — so there's no emulation overhead. Both publish a GitHub Release artifact on success.

Trigger either workflow from the Actions tab using workflow_dispatch, or push to main to run both automatically.

Internals

How the ISO is structured.

Bastille uses Debian's live-build toolchain. Configuration lives in build/config/: package lists in package-lists/, chroot hooks in hooks/live/, and static files overlaid at includes.chroot/.

The root filesystem is packed into a squashfs image (-comp xz -b 1M) and embedded in the ISO alongside the kernel and initrd. On ARM64, live-boot mounts the squashfs over a tmpfs — the system runs entirely in RAM and touches the boot device only for the initial read.

The boot chain on ARM64 is EFI-only: grub-efi-arm64 loads EFI/boot/bootaa64.efi from boot/grub/efi.img. There is no i386-pc BIOS fallback. The GRUB menu passes boot=live components to live-boot and sets the hostname to bastille with user user.

Init is OpenRC with sysvinit-core as PID 1. elogind replaces systemd-logind for session management under GNOME. The greeter is greetd with a custom configuration.
